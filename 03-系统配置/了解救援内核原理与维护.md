# 说明

救援内核（Rescue Kernel）是 Fedora 在系统安装时创建的一个静态安全备份，用于在正常内核全部损坏时提供一个干净的恢复入口。

## 0. 创建原理

救援内核由 `kernel-install` 在系统安装时自动生成：

```text
# 生成流程
安装程序运行 kernel-install
复制当前内核 vmlinuz → /boot/vmlinuz-0-rescue-<machine-id>
生成对应 initramfs → /boot/initramfs-0-rescue-<machine-id>.img
创建 BLS（Boot Loader Specification，引导加载器规范）entry → /boot/loader/entries/<machine-id>-0-rescue-<machine-id>.conf
```

- **BLS（Boot Loader Specification）配置文件内容**

```text
title Fedora Linux (0-rescue-<machine-id>) 44 (KDE Plasma Desktop Edition)
version 0-rescue-<machine-id>
linux /@boot/vmlinuz-0-rescue-<machine-id>
initrd /@boot/initramfs-0-rescue-<machine-id>.img
options root=UUID=... ro rootflags=subvol=@
```

其中 `<machine-id>` 取自 `/etc/machine-id`。

- **GRUB 排序**

Fedora 的 GRUB 使用 `blscfg` 模块在启动时读取 `/boot/loader/entries/*.conf`，按 `version` 字段排序生成菜单：

```text
version=0-rescue-<machine-id>   ← 排最前
version=7.0.13-200.fc44
version=7.0.14-201.fc44
version=7.1.3-200.fc44          ← 当前内核
```

⚠️ 注意：排序依据的是 conf 文件内的 `version` 字段，不是文件名。

## 1. 救援内核 vs 旧版内核

| 特性 | 旧版内核 | 救援内核 |
| ------ | --------- | --------- |
| 创建方式 | dnf 安装内核包时自动生成 | kernel-install 在系统安装时创建一次 |
| 更新方式 | 每次内核更新重建 initramfs | 永不更新（静态） |
| 保留策略 | 保留最近 3 个版本 | 永久保留 |
| 模块目录 | /lib/modules/\<version\>/ 保留 | /lib/modules/\<初始版本\>/ 可能被清理 |
| 设计目的 | 正常使用 | 紧急恢复 |

## 2. 为什么救援内核会失效

安装系统时内核版本为 7.0.13，救援内核创建完成，启动正常。

第一次内核更新（7.0.13 → 7.0.14），`/lib/modules/7.0.13/` 仍在，救援内核仍能找到对应模块，启动正常。

第三次内核更新后（7.0.13 → 7.0.14 → 7.1.3），`/etc/dnf/dnf.conf` 中 `installonly_limit=3`，dnf 自动清理 `/lib/modules/7.0.13/`。救援内核启动时 initramfs 找不到对应模块，启动失败。

- **根本原因**

救援内核是静态的，但它依赖的旧模块目录会被 dnf 清理。

## 3. 修复方法

```bash
# 1. 更新 vmlinuz 为当前内核版本
sudo cp /boot/vmlinuz-$(uname -r) /boot/vmlinuz-0-rescue-<machine-id>

# 2. 使用当前内核模块重建 initramfs
sudo dracut --force /boot/initramfs-0-rescue-<machine-id>.img $(uname -r)

# 3. 更新 GRUB
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
```

- **验证**

```bash
ls -la /boot/vmlinuz-0-rescue-*
ls -la /boot/initramfs-0-rescue-*
ls /boot/loader/entries/ | grep rescue
```

## 4. loader entry 缺失时重建

```bash
sudo kernel-install add 0-rescue-<machine-id> /boot/vmlinuz-0-rescue-<machine-id>
```

如果提示 `Cannot find module directory`，这是已知问题——initramfs 已被 `dracut --force` 单独重建，`kernel-install` 的失败可以忽略。只需确认 `.conf` 文件已生成并更新 GRUB。

## 5. 常见问题

- **不修复救援内核会怎样？**

没有任何影响。你仍有 3 个正常内核可作为后备。救援内核只在所有正常内核同时损坏时才需要，概率极低。

- **为什么不改文件名来调整 GRUB 顺序？**

GRUB 的 `blscfg` 模块按 conf 文件内的 `version` 字段排序，不是按文件名。改名无效。

- **为什么 rescue-xxx.conf 中有两个 machine-id？**

BLS（Boot Loader Specification）conf 文件命名规则是 `<machine-id>-<titlesort>-<version>.conf`。`kernel-install add` 使用 `0-rescue-<machine-id>` 作为 version 参数时，文件名可能包含重复的 machine-id，不影响功能。
