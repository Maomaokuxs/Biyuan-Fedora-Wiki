# 说明

Fedora 系统默认采用的是 zram（内存压缩技术）作为交换空间，将数据写入内存，而内存是断电即清空的，所以有需要可以使用休眠来保持当前系统运行状态。

在使用休眠时，Fedora 提供的内核开启安全启动时，内核会进入 lockdown 模式，禁止将内核内存写入磁盘，从而阻止休眠。硬核一点的话可以自己重新编译内核，下文中不涉及，默认将安全启动关闭，如果需要使用安全启动的话，看自己的取舍。

需要注意的是根分区使用的 btrfs 文件系统。

## 0. 关闭安全启动

进入 BIOS 关闭安全启动。

```bash
mokutil --sb-state
```

需要输出为： SecureBoot disabled 再进行下面的步骤。

## 方式一：配置休眠文件

### 1.创建独立子卷 @swap

```bash
# 1.挂载 Btrfs 顶层 (ID=5) 到临时目录
sudo mount -t btrfs -o subvolid=5 /dev/nvme1n1p5 /mnt
# 假设根目录挂载在 /dev/nvme0n1p5 ，该分区使用的是 btrfs 文件系统

# 2.创建与 @、@home 平级的子卷
sudo btrfs subvolume create /mnt/swap

# 3.创建挂载点并卸载临时目录
sudo mkdir /swap
sudo umount /mnt
```

### 2. 配置自动挂载

```bash

# 0.备份当前的 fstab 文件
sudo cp /etc/fstab /etc/fstab.bak

# 1.获取 UUID (假设根分区 UUID 为 nvme1n1p5)
lsblk -f | grep nvme1n1p5

# 2.写入 fstab
echo 'UUID=你的UUID  /swap  btrfs  subvol=swap,compress=no,noatime 0 0' | sudo tee -a /etc/fstab
echo '/swap/swapfile none swap defaults,pri=-1 0 0' | sudo tee -a /etc/fstab
sudo mount -a
```

### 3. 创建休眠文件

⚠️注意：休眠文件的大小按照内存大小而定，我将其设置为了 16G 的大小。

```bash
sudo btrfs filesystem mkswapfile --size 16G /swap/swapfile
sudo swapon /swap/swapfile
```

### 4.SELinux 与权限对齐

```bash
# 1.定义目录本身：
sudo semanage fcontext -a -t swapfile_t "/swap"

# 2.定义具体的交换文件：
sudo semanage fcontext -a -t swapfile_t "/swap/swapfile"

# 3.强制应用：
sudo restorecon -v /swap
sudo restorecon -v /swap/swapfile


# 4.验证规则库
sudo semanage fcontext -lC
```

### 5.注入内核参数与重构引导

```bash
# 1.获取偏移量
OFFSET=$(sudo btrfs inspect-internal map-swapfile -r /swap/swapfile)
UUID=$(findmnt -nvo UUID /)

# 2.使用 grubby 写入参数
sudo grubby --update-kernel=ALL --args="resume=UUID=$UUID resume_offset=$OFFSET"

# 3.配置 dracut 恢复模块并重新生成
echo 'add_dracutmodules+=" resume "' | sudo tee /etc/dracut.conf.d/resume.conf
sudo dracut -f
```

### 6.重启电脑

重启后使用下面的命令测试休眠

```bash
sudo systemctl hibernate
```

## 方式二：使用独立 Swap 分区（推荐）

> 当根分区为 Btrfs 且存在多个设备加入存储池时，swapfile 存在跨设备分配导致内核无法识别的问题。使用独立 swap 分区可彻底规避此类问题。

### 1. 创建 Swap 分区

使用 `cfdisk` 交互式创建分区（按方向键选择，Enter 确认）：

```bash
sudo cfdisk /dev/nvme0n1
```

操作步骤：

1. 选择空闲空间，按 `[New]`
2. 输入分区大小（如 `16G`），Enter
3. 按 `[Type]`，输入 `linux-swap` 或编号 `19`，Enter
4. 按 `[Write]`，输入 `yes` 确认写入
5. 按 `[Quit]` 退出

### 2. 格式化并启用

```bash
sudo mkswap /dev/nvme0n1p6
sudo swapon /dev/nvme0n1p6
```

### 3. 获取 PARTUUID 并写入 fstab

```bash
# 查看 PARTUUID
ls -la /dev/disk/by-partuuid/ | grep nvme0n1p6

# 写入 fstab（示例 PARTUUID 替换为实际值）
echo 'PARTUUID=你的PARTUUID none swap defaults 0 0' | sudo tee -a /etc/fstab
```

### 4. 配置内核参数与重构引导

> ⚠️ 独立 swap 分区使用 `PARTUUID` 而非 `UUID`，避免 Btrfs 多设备同名歧义。Swap 分区不需要 `resume_offset`。

```bash
# 清理旧参数，写入新 resume
sudo grubby --update-kernel=ALL --remove-args=resume \
  --args="resume=PARTUUID=你的PARTUUID"

# 启用 dracut resume 模块
echo 'add_dracutmodules+=" resume "' | sudo tee /etc/dracut.conf.d/resume.conf

# 重建 initramfs 并更新 grub
sudo dracut --force
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
```

### 5. 验证

重启后测试：

```bash
sudo systemctl hibernate
```

如果 systemd 拒绝休眠但 `echo disk | sudo tee /sys/power/state` 可以成功，通常是 swap 分区容量小于当前已用内存，扩容至 ≥ 已用 RAM 即可。

### 故障排查

| 症状 | 原因 | 修复 |
| ------ | ------ | ------ |
| `invalid environment block` | grubenv 损坏 | `sudo rm -f /boot/grub2/grubenv && sudo grub2-editenv /boot/grub2/grubenv create` |
| `Specified resume device is missing` | PARTUUID 错或 swap 太小 | 检查 fstab 中的 PARTUUID，扩容 swap |
| systemd 拒绝但内核方式有效 | systemd 容量预检过严 | 扩容 swap 或临时用 `echo disk \| sudo tee /sys/power/state` |
| Btrfs swapfile 跨设备 | 多设备池中创建了 swapfile | 改用方式二（独立分区）或从池中移除非必要设备 |
